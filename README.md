# נסיעות שיתופיות — כלי לניהול נסיעות משותפות בין עמיתים לעבודה

מי נוסע מחר, מי מצטרף, ומי חייב למי — במקום אחד, בלי לחפש בצ׳אט או במייל.

### ▶ [כניסה לכלי](https://carpool-il.netlify.app)

אפשר גם ללחוץ שם על **"הצצה בלי הרשמה"** ולראות את הכלי מלא עם נתוני דוגמה,
בלי חשבון. ההצצה רצה בדפדפן שלכם בלבד ושום דבר בה לא נשמר.

## מה הוא עושה

לכל נהג יש מרחב משלו שבו הוא מעדכן מתי הוא נוסע — נסיעה בודדת או נסיעה קבועה
שמתפרסמת אוטומטית לחודש קדימה. נוסעים מצטרפים בלחיצה, הנהג מאשר (או מגדיר
אישור אוטומטי), והנסיעה נכנסת להיסטוריה לבד אחרי שהיא מתבצעת.

הכסף מנוהל בשרשרת סטטוסים ברורה:

```
חוב פתוח → הנוסע מסמן "שילמתי" → ממתין לאישור הנהג → אושר ✓
```

לנוסע יש דשבורד של נסיעות, תשלומים וחובות; לנהג יש דשבורד כולל; ולמנהל יש
תמונה ארגונית — תפוסה, חיסכון, חובות פתוחים וסגירת חודש.

---

## כניסה

רגילה, כמו בכל אתר: **חשבון Google** או **מייל וסיסמה**, עם שחזור סיסמה עצמאי
דרך קוד שנשלח למייל.

קוד הצוות נדרש **פעם אחת בלבד**, בתוך האתר אחרי הכניסה הראשונה, ולא בכל
התחברות. גם אז אפשר לדחות אותו ולהזין מתי שרוצים.

---

## שלושת התפקידים

אדם אחד יכול להיות גם נהג וגם נוסע.

- **נהג** — מפרסם נסיעות, קובע מחיר ומקומות, מאשר בקשות, סוגר נסיעה, מאשר תשלומים.
- **נוסע** — מצטרף, מקבל עדכונים, רואה חובות, מסמן תשלום, מוסיף ידנית נסיעה שנסע.
- **מנהל** — מאשר חברים, קובע מדיניות, מנהל נקודות איסוף, סוגר חודש.

## פרטיות

- **בלי כניסה — אפס גישה.** לכל הטבלאות יש הגנה ברמת השורה, ולמשתמש אנונימי
  אין הרשאות בכלל. פנייה ישירה למסד הנתונים מוחזרת עם "אין הרשאה".
- **טלפון נחשף רק למי שנוסע איתך בפועל** ולמנהל — לא לכל הארגון.
- **חיובים ותשלומים** נראים רק לשני הצדדים ולמנהל.
- **בקוד אין שום נתון אישי.** כל המידע יושב במסד הנתונים מאחורי כניסה.
- **כל שינוי סטטוס מתועד** עם מי ומתי, כדי שמחלוקת כספית תהיה פתירה.

**הכלי אינו אמצעי תשלום.** הכסף עובר בין האנשים ישירות; הכלי רושם ועוקב בלבד.

## פיתוח

```bash
npm ci
npm run dev      # פיתוח מקומי
npm run build    # בנייה
```

הבנייה דורשת שני משתני סביבה: `VITE_SUPABASE_URL` ו-`VITE_SUPABASE_ANON_KEY`
(ובנוסף `VITE_VAPID_PUBLIC_KEY` להתראות דחיפה). אין להם ערך ברירת מחדל בקוד
בכוונה: בלעדיהם הכלי נעצר בטעינה עם הודעה ברורה, במקום להצביע בשקט על מסד
נתונים לא נכון.

> ⚠️ בסביבות מסוימות כבר מוגדר `VITE_SUPABASE_URL` של פרויקט אחר, ו-Vite
> קולט אותו בשקט. אחרי בנייה כדאי לוודא שהכתובת שנצרבה היא הנכונה:
> ```bash
> grep -o 'https://[a-z0-9]*\.supabase\.co' dist/assets/*.js | sort -u
> ```

פריסה: בונים ומעלים את תיקיית `dist` לשירות האירוח.
ההסבר איך לחבר פרסום אוטומטי נמצא ב[מדריך ההקמה](docs/04-מדריך-הקמה.md).
