# בדיקות

שתי חבילות. שתיהן רצות אוטומטית בכל דחיפה ובכל בקשת מיזוג, וגם ידנית.

| מה | פקודה | מה צריך בשבילה |
|---|---|---|
| קוד, טיפוסים ופריסה | `npm test` | כלום |
| מסד הנתונים | `npm run test:db` | Postgres מותקן במחשב |
| הכל | `npm run test:all` | Postgres מותקן במחשב |

## בדיקות מסד הנתונים — `tests/db/`

**מה הן בודקות:** לא שהממשק מסתיר כפתור, אלא שמסד הנתונים עצמו חוסם. מי
שרוצה לעקוף לא ישתמש בממשק, ולכן כל בדיקה כאן מדברת ישירות עם המסד בזהות
של משתמש מסוים.

הבדיקות מריצות את **קבצי המיגרציה האמיתיים** מ-`supabase/migrations/`, לפי
הסדר, על מסד נקי. כלומר הן בודקות את מה שבאמת נפרס ולא העתק שלו.

| קובץ | מה יש בו |
|---|---|
| `00_env.sql` | מדמה את מה ש-Supabase מספק ואין ב-Postgres רגיל: תפקידים, סכמת `auth`, הרשאות ברירת מחדל |
| `01_helpers.sql` | ארבע פונקציות עזר, כדי שכל בדיקה תיקרא כמו משפט אחד |
| `10_seed.sql` | שני ארגונים ושישה חשבונות, שנבנים דרך אותן פונקציות שהכלי משתמש בהן |
| `20_security.sql` | מי לא רשאי למה — אורח, משתמש רגיל, גבולות בין ארגונים, שומרי העמודות |
| `30_admin_console.sql` | מה מנהל המערכת רואה, ושהמספרים נכונים |
| `40_suspension.sql` | השהיה של משתמש ושל ארגון, והחזרה ממנה |
| `50_deletion.sql` | מחיקה, מה נמחק איתה, ומה נשמר |
| `90_report.sql` | סיכום, ונכשל אם בדיקה אחת נכשלה |

**כשבדיקה נכשלת** מודפס שמה והסיבה, והריצה מסתיימת בקוד שגיאה. אין מצב
שכישלון עובר בשקט.

### הוספת בדיקה
```sql
select t_check(:SUITE, 'שם הבדיקה בעברית', <תנאי שאמור להיות אמת>);
select t_denied(:SUITE, 'פעולה שחייבת להיחסם', 'ה-SQL שאמור להיכשל');
select t_allowed(:SUITE, 'פעולה שחייבת לעבור', 'ה-SQL שאמור לעבוד');
select t_count('שאילתה') -- כמה שורות המשתמש הנוכחי באמת רואה
```
להחלפת זהות: `set role authenticated; select t_login('<מזהה משתמש>');`
ולאורח לא מזוהה: `set role anon; select t_login(null);`

## בדיקת הפריסה — `tests/ui/check-layout.mjs`

בודקת שהריפוד מעל סרגל הניווט התחתון לא נדרס. זו הייתה תקלה אמיתית שלא
הרעישה: מחלקת הריפוד הוגדרה בשכבת `base` של Tailwind, ושם היא מפסידה לכל
מחלקת ריפוד רגילה על אותו רכיב — ושורת הכפתורים האחרונה הסתתרה מאחורי
הסרגל בכל מסך בכלי, בלי שום שגיאה.

רצה בלי דפדפן ובלי תלויות. בדיקת ה-CSS הבנוי מדלגת על עצמה אם אין `dist`,
ולכן להרצה מלאה כדאי `npm run build` לפניה.

## מה עדיין לא מכוסה

- **פונקציות השרת** (`supabase/functions/`) — רצות ב-Deno מול שירותים
  חיצוניים, ואין להן בדיקה אוטומטית. שינוי בהן נבדק ידנית.
- **המסכים עצמם** — נבדקים ידנית בדפדפן. הבדיקה האוטומטית מכסה את הפריסה
  ואת הטיפוסים, לא את ההתנהגות.
- **המשימות המתוזמנות** — `pg_cron` אינו קיים מחוץ ל-Supabase, ולכן
  הפונקציות שהן מריצות נבדקות אבל התזמון עצמו לא.
